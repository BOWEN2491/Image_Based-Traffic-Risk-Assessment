# Prediction API

`POST /api/predict` accepts one JPEG, PNG, or WebP upload in the `file` form
field. The default response keeps the existing prediction fields and omits
image geometry and detections.

Pass `?include_detections=true` to add `image_size` and `detections`. The
details are captured from the same detector invocation used to build the
assessment features; the API does not run perception a second time. At most
300 supported objects are returned. Each bounding box is normalized `xyxy`
in `[0, 1]` against the EXIF-oriented image dimensions. `confidence` is the
detector score, not a risk probability. `traffic_light_color` is populated only
for traffic lights and is `null` for other categories. In rules mode traffic
light colors remain `unknown`.

Responses include `reason_code`. The frontend maps known codes to explanations
and suggestions, retains the service's original `reason`, and falls back to
that text for older responses without a reason code or for future unknown
codes. A detection overlay can be hidden independently of the assessment.

`docs/NEXT_ITERATION_AGENT_PLAN.md` describes the full response and compatibility
contract. OpenAPI generated by the application remains the executable schema.
